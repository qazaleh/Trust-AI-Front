# Repository Guidelines

## Project Structure & Module Organization

This repository is primarily a Vue 3 + Vite frontend. `src/main.js` mounts `App.vue`, the router, `vue-i18n`, the reveal directive, and global styles. Route-level pages live in `src/views`, shared components in `src/components`, shadcn-vue/Reka UI primitives in `src/components/ui`, helpers in `src/lib`, routing in `src/router`, and locale sources in `src/i18n/*.json`. Compiled i18n runtime files are stored under `src/i18n/compiled` and regenerated by the build hooks. Static assets served from the site root live in `public`; importable source assets can live in `src/assets`. `dist` is build output. `Nuxt/` contains a separate Nuxt app; run its commands from that directory when working there.

## Build, Test, and Development Commands

- `npm install`: install root project dependencies.
- `npm run dev`: compile i18n messages, then start the Vite dev server.
- `npm run build`: compile i18n messages and create the production build in `dist`.
- `npm run preview`: compile i18n messages and serve the production build locally.
- `npm run compile:i18n`: regenerate compiled locale modules from `src/i18n/*.json`.
- `cd Nuxt && npm run dev`: start the nested Nuxt app when modifying `Nuxt/`.

## Coding Style & Naming Conventions

Use Vue single-file components with the Composition API and `<script setup>` for new root-app components. The root app is JavaScript, not TypeScript. Follow existing formatting: 2-space indentation, single quotes in JavaScript imports/strings, and no semicolons. Prefer the `@/` alias for imports from `src`. Name reusable components in PascalCase, for example `PageHero.vue`; match nearby route-file conventions for view files. Keep design tokens and broad Tailwind layer utilities in `src/styles/globals.css`, and prefer lucide icons when adding icon buttons or UI affordances.

## Testing Guidelines

No automated test runner is currently configured in the root `package.json`. Before submitting changes, run `npm run build` and manually verify affected routes in `npm run dev` or `npm run preview`. If adding tests, add the test tool and script explicitly, place tests near the code or under `src/__tests__`, and use clear names such as `ComponentName.spec.js`.

## Commit & Pull Request Guidelines

Recent commits use short, imperative summaries such as `Fix governance playbook download`, `Update asset references...`, and `add cursor-pointer...`. Keep commits focused and describe the user-visible change. Pull requests should include a concise summary, linked issue or task when available, screenshots for visual changes, and the exact verification performed, especially `npm run build`.
